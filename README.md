# SFTP JSON Client

Консольное приложение на Java SE 8 для управления списком пар "Домен-IP" в JSON-файле на удаленном SFTP-сервере. Проект включает в себя как сам клиент, так и отдельный модуль автоматизированного тестирования.

## Ссылка на проект автотестов:
https://github.com/Acrist671/sftp-testing
## Соответствие требованиям
- **Язык:** Java SE 8.
- **Зависимости:** Только `JSch` (для SFTP) в клиенте и `TestNG` (в проекте тестов).
- **Платформа:** Linux (код полностью кроссплатформенный, протестирован на Linux/Windows).
- **Валидация:** Проверка формата IPv4 и уникальности доменов/IP.

## Подготовка и запуск
1. Разверните docker-контейнер командой:
   
   ```
   docker run -p 22:22 -d atmoz/sftp foo:pass:::upload
   ```
   
2. Убедитесь, что установлена **Java 8** (`java -version`).

3. Сборка (опционально, если выбрали путь сборки, то шаги запуска проекта и тестов отличаются):
   ```
   mvn clean package
   ```
   изменение шага запуска проекта:
   ```
   java -jar jars/sftp-json-client-1.0-SNAPSHOT.jar
   ```
   изменение шага запуска автотестов:
   запускаем с использованием флага -Dclient.jar.path=<Ваш_абсолютный_путь>
5. Запустите проект (Запускается через консоль открытую в корне проекта):
   ```
   java -jar jars/sftp-json-client-1.0-SNAPSHOT.jar
   ```

## Работа с клиентов

### Параметры подключения
1. хост: localhost
2. порт: 22
3. логин: foo
4. пароль: pass

### Меню
1. Получить список: Выводит все пары, отсортированные по домену.
2. Найти IP по домену: Возвращает IP, при отсутствии просто ничего не возвращает.
3. Найти домен по IP: Возвращает домен, при отсутствии просто ничего не возвращает.
4. Добавить запись: Запрашивает домен и IP с валидацией на формат и уникальность.
5. Удалить запись: Позволяет удалить запись, введя либо домен, либо IP, при отсутствии просто ничего не возвращает.
6. Завершить работу: Безопасно закрывает SFTP-сессию и завершает программу.

## Обоснование тестов
### Архитектурный выбор: e2e
Выбранный подход реализует тестирование уровня Black Box (черный ящик) через эмуляцию консоли.

Инструментарий: Использован фреймворк TestNG для управления жизненным циклом тестов и .assertions.

Соответствие требованиям: Имитируют поведение expect-скрипта в linux.

### Покрытие функционала
Разработанный набор тестов покрывает ключевые сценарии использования приложения:
1. Инициализация соединения (testConnectionAndMenu)
2. Валидация входных данных (testAddInvalidIp)
3. Бизнес-логика добавления данных (testAddValidAddress)
4. Проверка уникальности данных (testAddNotUniqueDomain)
5. Функционал поиска (getIpByValidDomain, getDomainByValidIp)
6. Очистка данных и проверка работы удаления (deleteAddressByDomain)
